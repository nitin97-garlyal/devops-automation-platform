GitLab CI/CD Strategy

Our primary pipeline will be defined in .gitlab-ci.yml using GitLab Runners. It will execute test stages, build container layers using Docker-in-Docker (dind) or Kaniko, and push images to GitLab Container Registry.

  • Stage 1: test (Python 3.12 image, pytest, coverage report)
  • Stage 2: security (Trivy scan for vulnerabilities)
  • Stage 3: build (Docker build & tag with git commit SHA)
  • Stage 4: deploy (Kubernetes cluster rollout)

Jenkins Alternative Pipeline

As required by project guidelines, a dedicated Jenkinsfile will be built in a subsequent phase providing a declarative pipeline alternative for Jenkins CI/CD servers.

Scheduled after GitLab CI
